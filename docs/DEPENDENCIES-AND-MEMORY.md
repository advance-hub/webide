## 已修复的内存问题

| 位置 | 原因 | 当前行为 |
| --- | --- | --- |
| RPC 连接 | 调用者取消令牌一直持有已完成请求的监听及连接闭包 | 响应、错误、超时、发送失败和连接关闭都会释放；流式请求到结束或错误才释放，首块返回后仍可取消 |
| IDE 认证状态 | 未消费票据和过期会话留在普通 Map，无访问时也不清理 | 使用有界过期表，每 30 秒清理；两张表各最多 10,000 个有效项，满额返回 429，不淘汰有效会话；定时器随代理销毁且不阻止退出 |
| IDE WebSocket 代理 | 慢客户端导致发送缓冲继续增长，关闭后留下空工作区集合 | 单条消息和单端待发送数据均限制为 32 MiB，入队前检查；超限或发送失败终止两端，空集合删除，关闭过程中迟到的握手取消 |
| IDE 启动失败日志 | 读取整份日志再截取末尾，V8 字符串切片可能保留整个字符串 | 最多读取末尾 16,000 字节，再返回末尾 4,000 个 UTF-16 单元，并在所有路径关闭文件句柄 |
| 运行时指纹 | 逐个文件整体读取，大文件产生不必要的临时缓冲 | 按相同次序流式读取并更新哈希，摘要算法、输入和结果保持一致 |

票据仍有效一分钟，会话仍有效八小时。WebSocket 超限会断开连接，客户端需重新连接；本轮没有实现逐消息流控或把缓冲限制解释为整个 Server 的内存上限。单条消息上限与现有核心 IDE 通道一致，配置语义参考 [ws 官方 API](https://github.com/websockets/ws/blob/master/doc/ws.md)。

## 可复现的局部内存对照

macOS ARM64、Node 24.16.0。前后都使用本轮锁文件依赖，只对比指定函数的基线与当前实现，不是旧依赖版本和新依赖版本的总体性能比较。每种场景运行三个独立子进程，轮换前后顺序，显式执行 GC；票据场景推进时钟模拟十轮各 5,000 个过期入口，日志场景写入 64 MiB 文件并持有返回的尾部字符串。以下为三个结果的中位数，单位 MiB。

| 场景       | 原保留堆增量 | 当前保留堆增量 | 原 RSS 增量 | 当前 RSS 增量 |
| ---------- | -----------: | -------------: | ----------: | ------------: |
| 过期票据   |       13.003 |          0.214 |      55.688 |        53.703 |
| 大日志尾部 |       64.015 |          0.018 |      75.250 |         0.250 |

票据表从 50,001 项降到 1 项；长期存活取消令牌的 RPC 探针在每个调用完成后监听数量回到 0。堆减少不等于 RSS 同比例下降：票据场景仍有短期 URL/加密分配及分配器保留。机器结束时 load average 约为 `15.94/33.80/32.91`，本轮没有测量安静主机上的整棵 IDE P95、语言服务内存或延迟，不能承诺整个 IDE 按这些比例变轻。

## 后续维护规则

依赖检查只覆盖根包和包管理器声明的工作区，包含 `application/`，不扫描下载扩展、夹具和构建目录。`pnpm check:versions` 已纳入工程测试与现有 CI；两个回归探针分别验证真实版本漂移和第三方目录隔离。

更新时先查询官方注册表，再阅读跨主版本迁移说明；按组件栈拆批，更新所有实际调用方和锁文件，不删除对等依赖来掩盖冲突。通过类型、公开 API、相关测试与完整构建后，运行真实 IDE 和修改涉及的沙箱路径，最后按职责提交。第三方包仍使用原来的来源和许可证，本轮没有为它们建立私人 fork。

```sh
pnpm outdated -r --registry=https://registry.npmjs.org
pnpm install --frozen-lockfile
pnpm check:versions
pnpm check:product
pnpm typecheck:scripts
pnpm test:runtime-scripts
pnpm test:workbench
pnpm build:all
pnpm check:artifacts
node scripts/run-jest.js
```

本轮保留初次构建的 URI 声明错误和旧检查器的第三方目录误报，随后修复并重新验证；没有改写构建凭据来通过检查。

最终 Node 回归曾在 Docker 并行构建期间出现一次原生 watcher 未收到空文件新建事件的失败。对应套件独立重跑 17 项通过，失败日志仍保留；未放宽断言，也没有据此断言原因已确定或稳定性问题已修复。最终全量重跑结果另列在验收摘要中。

Windows、真实 Kubernetes、外部 Git 服务/云资源及整棵 IDE 的稳定性能对照仍需各自环境验收。
