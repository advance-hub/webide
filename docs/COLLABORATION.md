# 五人协同与运行边界

工作台的托管工作区默认启用 Node/Yjs 协同编辑。一个工作区最多邀请四位已登录并验证的账户，与所有者共同使用同一个 IDE Server。Go 运行引擎不参与任何入口。

## 账户与权限

所有者在工作区卡片中按登录用户名添加成员；同名或历史账户可使用工作台返回的账户摘要。成员列表保存稳定账户标识，展示昵称不参与鉴权。公开接口只返回账户摘要和显示名称，不返回代码源凭据。

`GET /api/workspaces` 返回本人和受邀的工作区，并明确标记 `accessRole: owner | member`。成员可查看运行状态、交换一次性入口票据并共同编辑；生命周期、成员管理、发布、开发机维护和资源配置接口仍要求原所有者。陌生账户或未受邀工作区统一返回 404。成员接口为 `POST /api/workspaces/:id/members`，请求包含 `username` 和可选布尔值 `remove`；重复添加或移除保持幂等。

邀请授予可信成员当前开发机的终端执行能力。这不是机器内部的文件隔离或只读共享：成员可通过终端操作该开发机上可访问的文件。工作台在邀请输入处说明此边界；不同账户各自拥有的开发机仍采用独立沙箱。需要不可信访客或文件级只读协作时，应增加独立运行环境和命令权限模型，不能仅隐藏控制面按钮。

首次共享前移除自动预置的私人数据连接，最后一位成员离开后恢复所有者配置。移除先持久化撤权，再清除成员的未消费票据和 IDE 会话、断开其已有代理连接；异步 WebSocket 握手在升级前再次检查授权。其他成员的连接保留。

同一工作区并发请求静态资源时合并环境查询，成功的就绪快照最多复用一秒，缓存与正在进行的查询各有 160 条上限。工作区生命周期版本改变后重新查询；查询失败不缓存。该缓存不保存成员授权，HTTP 在异步查询后再次检查会话，WebSocket 在升级前再次检查，撤权不等待快照过期。

官方 OpenSandbox SDK 客户端按沙箱 ID 和请求超时复用，同一键的并发连接只初始化一次。控制面最多持有 64 份活跃、待连接或待释放的客户端，空闲 30 秒后回收；容量满时先等待空闲传输完成释放，全部活跃时返回 503。任务失败后不再接纳旧客户端的新租约，但已有借用者可以完成；服务关闭取消迟到连接并排空租约。SDK 客户端关闭只释放 HTTP 传输，不停止或删除开发机。

## 协同通道与容量

托管 IDE 的客户端和服务端按同一运行声明加载协同模块。`/collaboration/y-room-opensumi` 与普通 IDE 通道复用已有 HTTP 入口、TLS、工作区域名和 Cookie 会话，不额外公开独立协同端口。代理覆盖工作区及账户头，去除浏览器 Cookie 和认证头后再注入运行时内部凭据。运行时管理路径在规范化后被代理拒绝。

OpenSandbox 的代理会过滤 `Authorization`，托管协同使用控制面覆盖的 `X-Opensumi-Runtime-Token` 应用头传递内部凭据；Node 校验固定长度凭据和工作区。该头不进入浏览器声明或公开环境接口。仅有普通 IDE 页面和 RPC 通道可用，不能判定协同通道已通过验收。

本机与沙箱启动入口统一设置 `ENABLE_COLLABORATION=1`、`COLLABORATION_TRANSPORT=shared`、`MAX_EXTENSION_HOSTS=5` 和 `MAX_MANAGED_EXTENSION_PROCESSES=5`。单人多个标签也占扩展宿主额度；超额连接不能挤掉已经在线的用户。每工作区代理有 16 个物理 WebSocket 名额，五人的普通通道和协同通道共占十个。

本地扩展宿主在关闭的绝对期限到达后，底层树停止可能仍持有精确进程租约。下一次创建只对已退役的租约进行有期限等待，物理名额释放后重新检查服务和浏览器连接；活跃用户占满时立即拒绝，不临时扩大五进程上限。管理器排空会唤醒等待者并拒绝后续创建，防止刷新或一轮浏览器全部关闭后误拒绝下一轮成员。

逻辑通道打开请求在确认超时后会重发。服务端只对同一物理连接、路径和追踪标识重发确认，不重复执行握手或分配资源；客户端已就绪时忽略重复确认。新物理连接继续执行完整的运行计划握手，服务停止时仍拒绝新请求，不降低协议校验要求。

独立框架开发仍可使用 `pnpm dev:collaboration` 的原有独立端口模式。共享 watcher 继续显式启用：`OPENSUMI_NODE_WATCHER_MODE=shared`；它只在一个 IDE Server 内共享原生监听，不共享扩展宿主、语言服务或五台开发机。

ACP Agent 默认按需启动，`ai-native.acp.backgroundStartup` 默认为 `false`。打开 IDE 不再为了预热和查询历史会话启动 OpenCode；首次发送请求或显式打开历史仍启动 Agent。需要后台预热时可在设置中启用该选项。本轮内存夹具没有发送 AI 请求或打开历史，必须核对实际进程树中没有 OpenCode；结果不包含五人同时使用 AI 的额外占用。

协同 RPC 连接单独持有文档引用，销毁时释放自身租约，迟到的磁盘加载立即退租。共享房间仍保留既有文档数量、单文件、消息缓冲和 CRDT 状态上限；这些是应用边界，不能当作整个 IDE 的 RSS 上限。外部程序修改已有文件的完整冲突合并、长期大量离线编辑和崩溃后的未保存内容持久化不在本轮验收范围。

## 真实验收入口

```sh
WEBIDE_ACCEPTANCE_SUITE=collaboration \
WEBIDE_ACCEPTANCE_PREFLIGHT=1 \
WEBIDE_ACCEPTANCE_PLATFORM=linux/arm64 \
WEBIDE_ACCEPTANCE_IMAGE=opensumi-webide-workspace:collaboration-terminal-ready-20261002 \
WEBIDE_ACCEPTANCE_OUTPUT=output/runtime-profiles/collaboration-20261002/result.json \
bash scripts/run-local-sandbox-acceptance.sh
```

入口使用固定版本官方 OpenSandbox Server/execd、独立 Docker daemon、回环随机端口和测试账户；不会切换默认 Docker context。测试账户由验收入口创建，外部 GitLab 登录不包含在该探针中。

入口默认读取工作区镜像的架构，也可显式设置 `WEBIDE_ACCEPTANCE_PLATFORM=linux/amd64|linux/arm64`；官方 Server、execd 和 SDK 创建参数使用同一架构。上面的本轮镜像在 ARM 主机上原生运行。构建与注册表的本机代理配置属于测试环境，不是运行时版本变更。

`WEBIDE_ACCEPTANCE_PREFLIGHT=1` 在同一隔离环境先完成原有六阶段控制面回归，分别保存结果；省略时只运行协同探针。默认三轮，调试时可使用 `WEBIDE_COLLABORATION_ROUNDS=1`。探针为每个沙箱配置 4 CPU / 4 GiB 上限，上限不代表实际占用，也不代表默认 2 GiB 配置已覆盖五人大型仓库。

浏览器通过实际工作台邀请、认证入口和 Monaco 键盘操作完成编辑；完整文档由全选复制读取，再与真实磁盘文件核对，不向生产页面添加调试命令入口。终端命令通过浏览器输入，并核对真实磁盘回执，避免依赖 xterm 的渲染器文本结构。覆盖五人并发编辑、撤销重做保留他人编辑、离线重连、刷新、成员撤销、独立开发机隔离、五个活跃浏览器及终端下的 Server 停止。运行结束释放本轮沙箱、卷、浏览器和临时工作目录。

终端输入框可能在远端连接完成前已经渲染。连接和首份输出共同决定终端的 `aria-busy` 状态，探针等待就绪后再粘贴命令；重建终端会取消旧视图及输出等待。回执为空或不匹配的轮次仍保留为失败。

每种场景三轮：五人共享一个工作区，以及五人分别拥有独立工作区。预热 30 秒后采集 30 份进程树样本，记录每轮 P95 和三轮中位数。测量仅包括 IDE Server 的后代进程，不含 Chromium、控制面验收入口与 OpenSandbox 守护进程。镜像提供内置扩展，夹具为 100 个小型 TypeScript 文件；结果不能直接外推到 Java、大型仓库或构建任务，也不能与历史 OpenSumi 整仓实验相减来宣称内存降幅。

顺序固定为共享工作区三轮，再独立工作区三轮；各轮关闭并重新打开浏览器，场景内复用运行实例。主机负载逐样本保存，当前数据不用于吞吐或延迟对照。每份样本都核对扩展宿主数量和空闲 OpenCode 进程数；连接掉线或后台 Agent 被启动时不能给出本轮容量结论。主动断网、刷新、撤权及关闭期间的 RPC 关闭单独标记，原始浏览器错误全部保留；启动超时和正常在线期间的错误仍使验收失败。

探针启动时保存自身和浏览器辅助文件的 SHA-256，结束时再次核对；运行中发生修改时本轮标记失败。清理失败也保存到结果中，不能用已完成的编辑步骤替代资源释放验收。

失败保留浏览器截图、页面正文、容器资源与 OOM 计数、实际进程树和 IDE 日志。运行计划握手阻断页面还通过自身的诊断按钮保存错误原因与关联标识，避免仅凭错误代码推断版本不一致。

RSS 合计包含进程间重复计入的共享页，不能当作 PSS 或容器 cgroup 总内存；Docker 缓存、文件页缓存和守护进程另占内存。采样必须检查实际扩展宿主数量，五人共享有五个扩展宿主，每台独立开发机有一个。离线探针先逐份核对文档隔离，再恢复网络核对合并后的完整内容。

本轮实际结果与证据索引在验收完成后登记；当前文档不预填内存数字或宣称所有平台通过。
